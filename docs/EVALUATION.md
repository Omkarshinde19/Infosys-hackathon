# Evaluation results

Generated by `make eval` (300 held-out scenarios × 4 policies, 60 s of simulated time each). Raw runs and the summary: `docs/evaluation.json`; charts on the dashboard's Evaluation page.

Policies: `no_heal` detects and diagnoses only. `reactive` diagnoses with rules and applies the first detour, with no twin test and no guardrails. `twin` is NetHeal: rules + GNN diagnosis, twin-tested candidates behind the OPA guardrails. `predictive_twin` adds the forecaster and LSTM autoencoder (the live configuration).

## Reading these numbers

- `reactive` can recover a few more faults than `twin`: it ignores the blast-radius guardrail (at most 5 flows moved automatically), e.g. it moves every flow off a flapping internet uplink at once. NetHeal hands those to a human on purpose.
- An overloaded access switch has no detour (the traffic starts there), so every policy escalates it.
- No fix is rolled back: in the simulator every detour around the fault works, so testing on the twin first can't beat a plain detour on recovery here. Its value is safety (the guardrails see predicted load), and on real packets reality can differ.
- The forecaster's value is earlier detection of gradual faults. Diagnosing earlier occasionally names the wrong cause first; it is corrected before anything is applied.
